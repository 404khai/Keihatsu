**Issue 1: Category Not Showing Until Refresh**
*   **Cause**: In `OfflineLibraryProvider.dart`, the `createCategory` method calls `libraryRepo.createCategory(name)` and then `_loadCategories()`. While `_loadCategories()` calls `notifyListeners()`, the issue is likely that `_loadCategories` relies on `libraryRepo.getCategories()` which queries Isar. Isar operations are asynchronous. If the write transaction in `createCategory` hasn't fully committed or the query runs too fast before the watcher updates (or if the watcher is not being used for this specific list), the UI might not get the new data immediately.
*   **Correction**: `OfflineLibraryProvider` is listening to `libraryRepo.watchCategoryAssignments()` but **NOT** `libraryRepo.watchCategories()` (or equivalent).
*   Looking at `OfflineLibraryProvider.dart`:
    ```dart
    void _init() {
      libraryRepo.watchLibrary().listen(...) // Updates _library
      libraryRepo.watchCategoryAssignments().listen(...) // Updates _categoryAssignments
      _loadCategories(); // Initial load
    }
    ```
    There is **no watcher for categories**. So `_categories` is only updated when `_loadCategories()` is manually called. While `createCategory` calls `_loadCategories()`, it might be that the UI (the `TabController` in `LibraryScreen`) isn't reacting to the change in the number of categories correctly, or `_loadCategories` is fetching stale data.
*   **Fix**: Add a watcher for categories in `LibraryRepository` and listen to it in `OfflineLibraryProvider`. This ensures any change to the `LocalCategory` collection (adds, updates, deletes) automatically updates the provider's `_categories` list and notifies listeners.
