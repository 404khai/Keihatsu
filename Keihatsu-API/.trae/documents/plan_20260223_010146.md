I have identified the causes for both issues:

1.  **Data Persistence (Isar not clearing on logout):** The `AuthProvider.logout` method currently clears only the `SharedPreferences` token but leaves the Isar database intact. Since Isar is a singleton and persistent, the next user inherits the previous user's data.
2.  **Category Overwrite (Bug in `createCategory`):** The `LocalCategory` model has a unique index on `serverId` (`@Index(unique: true, replace: true)`). When creating a local category, `serverId` is initially `null`. Isar treats `null` as a value for the unique index with `replace: true`. Thus, creating a second category (which also has `null` serverId) causes Isar to identify a conflict and *replace* the existing "null-serverId" category (the first one) with the new one, instead of creating a new record.

**The Fix Plan:**

1.  **Fix Category Creation:**
    *   Modify `LibraryRepository.createCategory` to assign a temporary, unique string to `serverId` (e.g., `local_${timestamp}`) instead of leaving it `null`.
    *   This prevents the unique index collision, allowing multiple unsynced categories to coexist.
    *   The `SyncManager` will later update this to the real `serverId` from the backend.

2.  **Fix Logout Data Clearing:**
    *   Modify `AuthProvider` to accept an optional `VoidCallback? onLogout` in its constructor.
    *   Update `AuthProvider.logout` to execute this callback.
    *   In `main.dart`, inject a callback into `AuthProvider` that performs `isar.writeTxn(() => isar.clear())`. This ensures the entire database is wiped clean when the user logs out.
