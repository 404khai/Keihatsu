I have identified the issue. The error "Failed to load pages: 404" occurs because the `chapterId` for ManhuaTop contains slashes (e.g., `manhua/manga-name/chapter-1`). When the frontend constructs the API URL, it inserts this ID directly into the path (`.../chapters/manhua/manga-name/chapter-1/pages`), which confuses the backend router (NestJS) as it looks like multiple path segments instead of a single ID parameter.

**The Solution:**
I will update `Keihatsu/lib/services/sources_api.dart` to URL-encode the `chapterId` (and `mangaId` for consistency) using `Uri.encodeComponent()`. This ensures the ID is treated as a single segment (e.g., `manhua%2Fmanga-name%2Fchapter-1`), which the backend will correctly decode and route.

**Steps:**
1.  Modify `Keihatsu/lib/services/sources_api.dart`.
2.  Update `getMangaDetails`, `getChapters`, and `getPages` to encode their ID parameters before inserting them into the URL string.

This is a standard fix for handling IDs containing slashes in RESTful APIs.
